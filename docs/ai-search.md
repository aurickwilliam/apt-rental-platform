# Ava: AI chatbot search (Gemini)

Ava (APT Virtual Assistant) is the tenant chatbot search on mobile (`app/search/ai-search.tsx`, opened from the sparkles button in the Explore header) and on the web (a right-hand drawer, `app/components/ava/`, opened from the sparkles button in the tenant Browse search row). Tenants describe what they want in plain English, Tagalog or Taglish. Ava replies in a friendly way and shows real listings.

## How it works

1. The chat hook (mobile `hooks/chat/useAIChat.ts`, web `hooks/use-ava-chat.ts`) sends the conversation to the `ai-search` edge function. Reading its answer, the keyword fallback and what Ava says are shared in `@repo/utils` `avaChat.ts` (`readAvaResponse`, `avaFallbackAnswer`, `shouldSearchForAva`, `composeAvaReply`), so both platforms behave the same.
2. The edge function (`supabase/functions/ai-search/index.ts`) checks the caller (signed in, not suspended), counts the message against the daily allowance, and asks Gemini for JSON: a short `reply`, up to four `quickReplies` and search `filters`.
3. The app runs every filter through `sanitizeAiFilters` (`@repo/utils` `aiSearch.ts`) and searches with its own client: mobile `fetchAvaListings` (same guards as the search tab), web `fetchAvaResults` (`app/browse/lib/fetch-ava-results.ts`, the same `applyBrowseFilters` / `applyBrowseSort` as Browse, so "See all results" opens exactly that search via `aiFiltersToBrowseParams`). RLS decides what is shown.

Gemini never writes listings, prices or addresses, so it cannot show a listing that does not exist.

## Memory, language and landmarks

All of this is shared by web and mobile in `@repo/utils` and runs on the device; the edge function only sees chat text plus a small `context` (language, current filters, current landmark name).

- **Conversation memory.** The chat stays in component state (no new history store). Each Ava reply remembers the search it ran (`search`: filters + landmark key) and the listing ids it showed (`shownIds`). The next message builds on that: `buildAvaRequest` sends the remembered filters to Gemini, the keyword fallback merges each message over the earlier ones (`mergeAiFilters`), "show me more" (`wantsMore`) skips the ids already shown, and "closer to it" or "more" keep the landmark; any other message that names no place ("with parking?", "what if my budget is 8k?") is a new search that keeps the budget, bedrooms and amenities but not the landmark. A new city or "any area" also drops it. Nothing is invented: if no search was remembered, Ava asks.
- **Memory is deterministic.** Gemini's filters are read as *this message's changes* and merged over the remembered search (`mergeAiFilters`), never as the whole truth: the model sometimes drops an earlier budget or bedroom count, which made the same question answer differently. Clearing something needs an explicit phrase ("any area", "any budget", "any unit type", "start over"). "Cheapest first" belongs to the message that asked for it. Each result reply ends with a one-line summary of what is being applied ("Searching: near SM City Grand Central · up to ₱8,000 · 2 bedrooms"), so a remembered landmark or budget is never a surprise.
- **Bedroom ranges.** "One or two bedrooms" / "1-2BR" is `bedrooms: '1'` with `bedroomsMax: 2` (`AiSearchFilters`), searched as a range by both platforms. Plain Browse cannot filter a range, so the web drawer hides "See all results" for one (`isBrowseExpressible`) and passes the range to its own query under `ava_bedrooms_*` keys.
- **Language.** English by default; Tagalog when the tenant writes Tagalog (`avaLanguage.ts`, rule-based). Short follow-ups ("2BR") keep the language of the conversation. If the model answers in the other language, its text is replaced by Ava's own wording (`detectReplyLanguage`, conservative: only clear Tagalog or clear English counts). The language is also sent to Gemini, and every non-model sentence (fallback, errors, all location results) comes from `avaStrings.ts` in that language.
- **Landmarks.** `packages/constants/src/camanava-landmarks.ts` is generated by `node scripts/landmarks/build-landmarks.mjs`: each entry is looked up in OpenStreetMap (ODbL), must fall inside CAMANAVA and near its city, and landmarks that cannot be found are left out (never guessed). `resolveLandmark` (`avaLandmarks.ts`) matches names, aliases and small typos without needing a city, treats "city hall" / "SM" as ambiguous (Ava asks which), turns "a hospital in Malabon" into every hospital there, and answers `unknown_place` for named places not in the list ("near Sampaguita School") instead of guessing. Add a landmark by adding an entry to the script and re-running it.
- **Distance search** (`answerAva`, `avaSearch.ts`). With a landmark, the app reads up to 500 matching listings anywhere in CAMANAVA (the landmark, not a city or keyword, decides where; `near_*` amenity filters are dropped) and ranks them by straight-line distance (`avaProximity.ts`, haversine on the listing's pin). Near is within 1.5 km, nearby within 5 km, otherwise "farther"; "cheapest first" reorders only the listings within 5 km, and "show me more" skips the ones already shown; Ava words each case differently and never calls a far listing near. Listings without a pin never get a distance; if none has a pin, Ava says it cannot measure and shows same-city matches. Distances are straight-line only; no travel times (no routing service is used). Each listing gets a one-line caption (distance, budget fit, bedrooms, requested amenities).
- **Limits.** The gazetteer is a curated list (malls, city halls, some schools, hospitals, a station and Monumento), not a full geocoder. Other places get "I can't pinpoint that yet". The 500-listing pool is enough for today's catalogue; revisit with a bounding-box query if it grows.

## History (web and mobile) and the full page (web)

- Conversations are saved **in the browser, per account** (`localStorage` key `apt-ava-chats:v1:{auth id}`, `lib/ava-history.ts`), never on the server, newest first, at most 30 chats of 60 messages. Only text, quick replies, the remembered search and listing **ids** are stored (`@repo/utils` `avaHistory.ts`); opening a chat re-reads those listings (`fetchAvaListingsByIds`, same visibility rules), so nothing stale or hidden reappears. `useAvaChat` owns it (`chats`, `openChat`, `deleteChat`, `resetChat`).
- The drawer has a History view (clock button) and an Expand button. Expand opens `/tenant/ava?chat=<id>` (`AvaPageClient`): a conversation sidebar plus the centred chat, built from the same `AvaChatView` the drawer uses.
- Mobile has the same history: `useAIChat(authUserId)` saves to AsyncStorage (`apt-ava-chats:v1:{auth id}`, `service/chat/avaHistoryStore.ts`), and the clock button in the header opens `AvaHistorySheet` (a kept-mounted bottom sheet) to open or delete a chat. There is no full-page view on mobile.

## When Gemini is not used

The edge function answers `{ source: 'fallback' }` or `{ source: 'limit' }` instead of a Gemini answer when:

- `GEMINI_API_KEY` is not set,
- Gemini is rate-limited (429), slow (20 second timeout), failing or returns unreadable JSON, or
- the account used its daily allowance (`limit`).

The app then reads the tenant's messages with `parseSearchKeywords`, a rule-based reader for city names, budgets ("under 15k", "hanggang 12 libo"), rooms ("2BR", "dalawang kwarto"), types, furnishing and common amenities. Search keeps working without the model.

## Setup

```bash
supabase secrets set GEMINI_API_KEY=<key from Google AI Studio>
```

Optional secrets:

- `GEMINI_MODEL`: model id. The default is `DEFAULT_MODEL` in the function. Free-tier models and their limits change often, so check Google AI Studio and pick a Flash or Flash-Lite model that is free on your project.
- `AI_SEARCH_DAILY_LIMIT`: messages per account per Asia/Manila day (default 30).

Then apply the migration and deploy the function (redeploy after this change: the prompt and schema now include `landmark` and `wantsMore`, and the function accepts `context`):

- Migration `supabase/migrations/20261028200000_ai_search_usage.sql` adds `ai_search_usage` and `consume_ai_search_allowance()`. Only the service role can use them.
- Deploy with `supabase functions deploy ai-search`. `verify_jwt = true` is set in `supabase/config.toml`.

Confirm the target project against the app's `EXPO_PUBLIC_SUPABASE_URL` before applying or deploying.

## Privacy

Free-tier Gemini prompts may be used by Google to improve its products. Only the typed chat text is sent (last 6 messages, 500 characters each). No profile data is sent, the chat shows a reminder not to share personal details, and the function never logs message text.

## Keeping lists in sync

The edge function keeps its own copy of the allowed cities, types, furnishing values and amenity ids for the Gemini prompt and schema, because Deno cannot import the workspace packages. If they drift, nothing unsafe happens: the app drops any value `sanitizeAiFilters` does not know. Update both `supabase/functions/ai-search/index.ts` and `packages/utils/src/aiSearch.ts` when adding a searchable amenity.
