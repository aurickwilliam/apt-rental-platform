# Bounded mobile chat history with stable realtime channels

The Batch 4 chat change replaces unbounded history loading with 30-message keyset pages, using descending `created_at` and `id` ordering so ties have a deterministic boundary. The active conversation predicate, apartment scope, and strict older-than composite cursor are emitted as independent conjunctive request filters; the generated PostgREST URL retains both `or` clauses, the apartment predicate, the order, and limit. The inverted `FlatList` keeps newest records at data index 0 and requests older records at the visual history edge, while one merge function removes duplicates across page loads, optimistic messages, and broadcasts. Channel setup now follows conversation identity rather than callback identity, with callback refs preventing reconnects during ordinary rerenders and effect cleanup removing both channels. Watch for: **confirmed, low severity**—the query behavior is unit-tested through a mock that does not evaluate PostgREST filters, so a live-Supabase/PostgREST integration test is still needed to prove the two `or` parameters are interpreted conjunctively in deployment.

**Verdict**: APPROVED

## High-level view

History uses a descending compound keyset. The cursor predicate is strictly older than the final row of the preceding page—an earlier timestamp or, for a tie, a lower UUID—so pages neither overlap nor omit tied timestamps under the declared database order.

The screen’s array order intentionally stays newest-first for `FlatList inverted`: new realtime and optimistic records enter at index 0, and fetched history appends to the array tail. The merge helper deduplicates by server/message ID while retaining each source’s supplied order, including init-versus-realtime races.

Realtime subscriptions are now an effect keyed only by `(currentUserId, otherUserId, apartmentId)`. Callback changes flow through refs, so a render does not churn websocket/presence channels; an identity change or unmount removes the exact channels created by that effect.

No RPC, schema, migration, index, Giphy-picker, or apartment-image behavior was changed in this Batch 4 scope. The apartment detail diff only adds favorite feedback and renames an image-map local variable; it does not alter image retrieval, URLs, or rendering behavior.

## Composite conversation cursor is deterministic

`fetchMessagePage` first limits the scope to either sender/receiver direction and to the requested apartment (or `apartment_id IS NULL`), then orders by `created_at DESC, id DESC`. With a cursor, it adds `created_at < cursor.createdAt OR (created_at = cursor.createdAt AND id < cursor.id)`. The installed PostgREST builder appends both `.or()` calls, producing a URL with the conversation predicate, apartment filter, cursor predicate, `created_at.desc,id.desc`, and `limit=30`; no later builder operation overwrites the earlier conversation predicate.

The cursor is taken from the last returned row only when a full page was returned. This permits one final empty request when the total is an exact multiple of 30, but cannot introduce a gap or duplicate: every subsequent page is strictly below its predecessor’s last compound key. The new unit/property test covers tied timestamps and asserts the cursor predicate shape, but **confirmed, low severity** it does not execute those filters against PostgREST, because its mock supplies each page independently of the query.

## Inverted history edge and concurrent message arrivals

The newest-first array agrees with `FlatList inverted`: index 0 is the visual bottom, and the array tail is the visual history edge. `onEndReached` loads only while `hasMore` is true; `paginationInFlightRef` prevents repeated threshold callbacks from issuing concurrent requests. Older pages merge at the tail, and `maintainVisibleContentPosition` preserves the current visible content as the history edge grows.

Incoming broadcasts merge at index 0. Initial and older pages merge without replacing current state, so a broadcast that arrives while either request is in flight survives; its ID is removed from the later page rather than appearing twice. Local sends replace their temporary ID with the inserted ID, while self-originated broadcasts are ignored and remote broadcasts share the same ID-based merge rule. These paths preserve the server’s descending order for every page and do not re-sort optimistic or broadcast data.

## Channel identity no longer follows render callbacks

The new effect creates message and presence channels only after `currentUserId` is available and is keyed precisely by the current user, peer, and apartment. Event callbacks are retained in refs, so callback-only rerenders dispatch to current handlers without changing channel identity. Cleanup clears the pending presence-track timeout and removes only the effect’s own channel instances, avoiding removal of a newer subscription during an identity change.

The hook test confirms callback-only rerenders retain the two original channels and invoke the replacement callback, while an identity change removes both old channels, creates both replacements, and unmount removes the replacements. It does not test asynchronous Supabase subscription status transitions.

## Deferred service and media work remains deferred

There are no changed SQL or migration files, no edits to `getConversations` or its `get_conversations` RPC call, and no index definitions. The Giphy picker is only pre-existing route/screen context; its URL/download behavior has no added or modified lines. The modified apartment detail screen changes favorite toast feedback and local naming only, leaving `apartment_images` mapping and image behavior intact.
